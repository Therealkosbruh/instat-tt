# Задание 1 - магазин с оплатой 

Фронт часть находится в `frontend-checkout-challenge/apps/web`

Проект выполнен на Next, в архитектуре fsd, для дальнейшего расширения и возможной SEO-оптимизации с генерацией уникальных метаданных на каждый товар

### Технологии и архитектура

|  |  |
| --- | --- |
| Next.js 16 (App Router) | маршрутизация, сборка |
| SCSS Modules | стили |
| TanStack Query | серверное состояние: каталог, корзина, заказ, оплата |
| React Hook Form + Zod | формы, валидация по схеме контракта |

Архитектура — FSD (`app/entities/features/widgets/shared`), зоны ответственности:

- `shared/api` - единая точка запросов к серверу: адрес, заголовки, токен, разбор ответа и ошибок в одном месте
- `shared/ui` - переиспользуемые компоненты (кнопка, поле формы, карточка выбора, статус-блок)
- `entities/*` - данные и типы ресурсов (товар, корзина, заказ, оплата, сессия) + хуки поверх `shared/api`
- `features/*` - пользовательские сценарии поверх нескольких entities (форма оформления, добавление в корзину, оплата тестовой картой)
- `widgets/*` - сборка entities/features в блоки страницы (шапка, каталог, корзина, страница заказа)
- `app/*` - маршруты Next

### Инструкции по запуску

Команды выполняются из `frontend-checkout-challenge` 

```sh
cd frontend-checkout-challenge
npm install
npm run build -w @checkout/contracts
```

Дальше - два терминала:

```sh
# терминал 1 — бэкенд, http://127.0.0.1:4000
npm run dev -w @checkout/api
```

```sh
# терминал 2 — фронтенд, http://localhost:3000
npm run dev -w @checkout/web
```

Сборка и продакшен-запуск фронтенда:

```sh
npm run build -w @checkout/web
npm run start -w @checkout/web
```

### Я бы улучшил

Корзина на сервере очищается сразу при создании заказа (`POST /api/orders`) - ещё до какой-либо попытки оплаты, для любого способа оплаты и независимо от её результата. Из-за этого при отказе или отмене оплаты картой у пользователя нет возможности сохранять айтемы в корзине - только сам заказ (доступен по прямой ссылке и через «Оплатить ещё раз»). Фактически ничего не теряется — состав, доставка и сумма заказа сохранены, оплату можно повторить — но с точки зрения UX это может сбивать с толку.

Я бы очищал корзину не в момент создания заказа, а при переходе заказа в оплаченное/подтверждённое состояние (`paid` для карты, `confirmed` для наличных). Тогда при отказе или отмене оплаты у пользователя останется исходная корзина.
